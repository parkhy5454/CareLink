# 내건강 — 9단계: 복약 알림 (아침/점심/저녁)

병원 예약 + 처방전 전송 + 약국 조제 앱의 아홉 번째 단계입니다. 처방전 사진에서 복용 기간을 읽어내서, 약국이 조제 완료 처리하면 그 기간 동안 아침·점심·저녁 식사 후 약 먹을 시간을 브라우저 알림으로 보내줘요.

## 이번 단계에서 새로 추가된 것

- **복약 알림**: 처방전을 분석할 때 Gemini가 "3일분", "1일 3회" 같은 복용 기간/횟수도 함께 읽어요. 약국이 **조제 완료** 처리하면, 그 순간부터 처방 기간 동안 매일 아침 8시·점심 12시·저녁 7시(한국시간 고정)에 "약 드실 시간이에요" 브라우저 알림이 자동으로 발송돼요
- 하루 1회 처방은 저녁에만, 2회는 아침·저녁, 3회 이상은 세 끼 모두 알림을 보내도록 매핑했어요
- Gemini가 복용 기간을 읽지 못하면(사진이 불명확하거나 표기가 없으면) 알림을 만들지 않아요 — 추측해서 잘못된 시간에 알림을 보내지 않도록 했어요
- 별도의 "복용 체크" 기능은 없고, 정해진 시간에 알림만 보내드려요 (필요하시면 나중에 추가할 수 있어요)
- 서버가 1분마다 발송 대기 중인 알림이 있는지 확인해서 웹 푸시로 보내요 (구독을 켜둔 브라우저에만 발송)

## 이전 단계에서 이미 만들어진 것

| 화면 | 주소 | 사용자 | 로그인 방식 |
|---|---|---|---|
| 환자 앱 | `/` | 일반 사용자 | 전화번호/이메일/구글/카카오/네이버 |
| 병원 대시보드 | `/hospital` | 병원 담당자 | 아이디/비밀번호 |
| 약국 대시보드 | `/pharmacy` | 약국 담당자 | 아이디/비밀번호 |
| 관리자 대시보드 | `/admin` | 운영자 | 아이디/비밀번호 (CLI로 최초 1명 발급) |
| 입점 신청 | `/apply` | 병원/약국 (로그인 불필요) | 없음 — 신청만 제출 |

- **계정 보안**: 이메일 비밀번호 재설정(재설정 코드 방식), 회원 탈퇴(연관 데이터 전체 삭제), 로그인/인증 시도 횟수 제한(IP당 일정 횟수 초과 시 429 응답), CORS를 `ALLOWED_ORIGINS`로 제한 가능
- **병원별 진료시간 설정**: 병원 대시보드에서 20개 슬롯 중 실제로 진료하지 않는 시간을 꺼둘 수 있어요. 끈 시간은 환자 화면에 아예 안 보여요
- **가족 관리 화면**: "내 정보 → 가족 관리"에서 가족 구성원 이름/관계/출생연도를 수정하거나 삭제할 수 있어요 (본인 프로필은 삭제 불가)
- **병원/약국 리뷰**: 확정된 예약(병원) 또는 조제 완료된 처방전(약국)에 대해서만 별점+한줄평을 남길 수 있어요. "내 정보 → 기록"에서 리뷰를 남기고, 예약 시간 선택 화면에서 병원 평균 별점을 볼 수 있어요
- **처방전 사진 저장**: 촬영한 처방전 사진이 이제 DB에 저장돼서, 약국 담당자가 대시보드에서 실제 사진을 다시 확인할 수 있어요
- **병원/약국 자체 입점 신청** (`/apply`): 로그인 없이 병원/약국을 검색해서 담당자 연락처와 함께 입점을 신청할 수 있고, 관리자가 승인하면 그 자리에서 계정이 자동 발급돼요
- **실제 처방전 사진 분석 (Google Gemini API)**: 처방전 화면에서 진짜 사진을 촬영하거나 갤러리에서 선택하면, Google Gemini API가 처방된 약 이름·성분·효능/효과·복용 시 주의사항을 분석해 보여줍니다
- **내 정보 (진료·처방 기록)**: 홈 화면 하단 탭에서 "내 정보"로 이동하면, 본인과 등록된 가족 전체의 진료 예약 + 처방전 내역을 시간순으로 볼 수 있어요
- **가족 구성원 예약**: 계정 하나로 본인 외에 자녀/배우자/부모님 등을 등록해두고, 예약할 때마다 누구를 위한 예약인지 선택할 수 있어요
- **병원/약국 대시보드에서도 구분**: 예약자(로그인 계정)와 실제 환자(가족 구성원)가 다르면 "예약자: 김엄마" 처럼 따로 표시돼요
- **예약 시간 선택**: 병원마다 요일 4개 x 시간 5개 = 20개의 예약 가능 시간표가 있고, 환자는 그중 **비어있는 시간만** 선택해서 예약할 수 있어요
- **동시 예약 충돌 방지**: 두 환자가 거의 동시에 같은 시간을 예약하려 하면, 먼저 처리된 쪽만 성공합니다 (DB 유니크 제약으로 이중 방어)
- **예약 승인 흐름**: 환자가 예약하면 `대기중` → 병원 담당자가 **확정** 또는 **거절** → 환자 화면에 실시간 반영(4초마다 자동 갱신)
- **처방전 수락/거절 흐름**: `대기중` → 약국 담당자가 **수락**/**거절**/**조제 완료** 처리 → 환자 화면(조제 현황)에 실시간 반영
- **역할 기반 권한**: 병원 계정으로는 약국 API에, 약국 계정으로는 병원 API에 접근할 수 없습니다
- **카카오 알림톡 알림**: 병원 확정/거절, 약국 수락/거절/완료 시 환자에게 알림 발송 (키 없으면 콘솔 로그 + 관리자 대시보드 "알림 이력"으로 대체)
- **회원가입 약관/개인정보 동의**: 온보딩 화면에서 필수 동의 체크 후에만 가입할 수 있어요 (문구는 데모용 예시, 실제 서비스 전 법률 검토 필요)
- **지도 기반 병원 검색**: 목록/지도 전환, "내 근처 병원 찾기"로 위치 기반 정렬 검색 (Leaflet + OpenStreetMap, API 키 불필요)
- **예약 취소**: 확정/대기중인 예약을 환자가 직접 취소할 수 있어요. 취소하면 그 시간은 다른 환자에게 다시 열려요
- **처방전 재전송**: 약국이 처방전을 거절하면 "다른 약국 찾기"로 검색해서 사진을 다시 찍지 않고 그대로 다른 약국에 재전송할 수 있어요
- **관리자 통계 그래프**: 최근 14일 예약/처방전 추이(라인 차트), 상태별 현황(막대 그래프)
- **자동화 테스트**: 54개 테스트로 핵심 흐름을 검증해요 (`npm test`, 자세한 내용은 아래 "자동화 테스트" 참고)
- **브라우저 웹 푸시**: "내 정보 → 계정"에서 "🔔 알림 켜기"를 누르면 예약/처방전 상태 변경 시 브라우저 알림을 받을 수 있어요. 사업자 인증 없이 VAPID 키만 발급하면 바로 동작해요 (카카오 알림톡과 동시에 발송)
- **AI 증상 체크**: 홈 화면에서 증상을 설명하면 Gemini가 적합한 진료과(내과/정형외과/피부과 등)를 이유와 함께 추천하고, 바로 그 진료과로 필터링된 병원 목록으로 이어져요. 우리 DB에 실제로 있는 진료과목 중에서만 추천하도록 제한했고, 응급 증상이면 119/응급실 안내가 먼저 떠요

## 병원/약국/관리자 담당자 계정 만들기

**관리자 계정은 최초 1개만 CLI로 만들면** 그 다음부터는 `/admin` 대시보드에서 병원/약국/관리자 계정을 직접 만들 수 있어요.

```bash
# 관리자 계정 (최초 1회, CLI로만 가능)
node server/create-staff.js admin <아이디> <비밀번호> [담당자이름]

# 병원/약국 코드는 /api/hospitals/search, /api/pharmacies/search 결과의 "code" 값을 사용하세요
node server/create-staff.js hospital <병원코드> <아이디> <비밀번호> [담당자이름]
node server/create-staff.js pharmacy <약국코드> <아이디> <비밀번호> [담당자이름]
```

예시:
```bash
node server/create-staff.js admin admin1 admin1234 "운영자"
node server/create-staff.js hospital JDQ4MTYyMi... hospital1 hosp1234 "김병원"
node server/create-staff.js pharmacy JDQ4MTYyMi... pharm1 pharm1234 "이약사"
```

병원/약국 코드를 모르면 검색 API로 먼저 찾아보세요:
```bash
curl "http://localhost:3000/api/hospitals/search?q=병원이름"
curl "http://localhost:3000/api/pharmacies/search?q=약국이름"
```

같은 아이디로 다시 실행하면 비밀번호가 갱신됩니다(재발급). 관리자 계정을 만든 뒤로는 `/admin` → "담당자 계정" 탭에서 병원/약국 이름을 검색해 바로 계정을 발급할 수 있어요 (CLI 필요 없음).

## Replit에서 실행하기

### 1. Postgres 데이터베이스 켜기
왼쪽 도구 목록에서 **Database**(PostgreSQL) 열기 → `DATABASE_URL` 자동 설정

### 2. 설치 + 데이터 적재
```bash
npm install
npm run seed
```

### 3. 관리자 계정 만들기 (최초 1회)
```bash
node server/create-staff.js admin admin1 admin1234
```

### 4. 실행
```bash
npm run dev
```
- 환자 앱: 배포 주소 그대로 (`/`)
- 병원 대시보드: 배포 주소 + `/hospital`
- 약국 대시보드: 배포 주소 + `/pharmacy`
- 관리자 대시보드: 배포 주소 + `/admin` (여기서 병원/약국 계정을 추가로 발급하면 돼요)

## 환경변수 정리

| 변수 | 설명 | 필수 여부 |
|---|---|---|
| `DATABASE_URL` | Postgres 연결 문자열 | 필수 (Database 도구 켜면 자동) |
| `JWT_SECRET` | 로그인 토큰 서명 키 (환자용/담당자용 공통) | 권장 |
| `GOOGLE_AI_API_KEY` | 처방전 사진 분석(Gemini API) | 선택 |
| `GOOGLE_AI_MODEL` | 사용할 Gemini 모델 (기본 `gemini-3.5-flash`) | 선택 |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` / `GOOGLE_REDIRECT_URI` | 구글 로그인 | 선택 |
| `KAKAO_CLIENT_ID` / `KAKAO_CLIENT_SECRET` / `KAKAO_REDIRECT_URI` | 카카오 로그인 | 선택 |
| `NAVER_CLIENT_ID` / `NAVER_CLIENT_SECRET` / `NAVER_REDIRECT_URI` | 네이버 로그인 | 선택 |
| `SOLAPI_API_KEY` / `SOLAPI_API_SECRET` | 카카오 알림톡/SMS 발송(솔라피) | 선택 |
| `KAKAO_SENDER_KEY` | 솔라피에 등록한 카카오 발신프로필 키(pfId) | 선택 |
| `KAKAO_SENDER_PHONE` | 알림톡 실패 시 대체 발송할 SMS 발신번호 | 선택 |
| `RESEND_API_KEY` | 비밀번호 재설정 이메일 발송(Resend) | 선택 |
| `MAIL_FROM` | 재설정 이메일 발신 주소 (기본 `onboarding@resend.dev`) | 선택 |
| `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` | 브라우저 웹 푸시 발송 키 | 선택 (권장) |
| `VAPID_SUBJECT` | 웹 푸시 발신자 정보 (기본 `mailto:admin@example.com`) | 선택 |
| `ALLOWED_ORIGINS` | CORS 허용 출처(콤마 구분). 안 정하면 전체 허용 | 권장 |
| `PGSSL` | `false`로 설정하면 SSL 없이 접속(로컬 개발용) | 선택 |
| `PORT` / `API_PORT` | 프론트/백엔드 포트 (기본 3000/3001) | 선택 |

소셜 로그인(구글/카카오/네이버) 설정 방법은 이전 단계 안내를 참고해주세요 — 동일합니다.

## 브라우저 웹 푸시 설정 방법 (권장)

카카오 알림톡과 달리 **사업자 인증이나 심사 없이 몇 초 만에 켤 수 있어요**.

1. 터미널에서 키 생성:
   ```bash
   node server/generate-vapid-keys.js
   ```
2. 출력된 두 값을 Replit **Secrets**에 추가:
   - `VAPID_PUBLIC_KEY`
   - `VAPID_PRIVATE_KEY`
3. 서버 재시작 (Stop → Run)

이제 환자 앱의 "내 정보 → 계정"에서 "🔔 알림 켜기"를 누르면 바로 동작해요. 설정 안 해도 앱은 정상 동작하고, 알림 켜기를 누르면 "아직 설정되지 않았어요" 안내만 뜹니다.

**참고**: 웹 푸시는 HTTPS(또는 localhost) 환경에서만 동작해요. Replit 배포 주소는 기본적으로 HTTPS라 별도 설정 없이 바로 됩니다.

## 비밀번호 재설정 이메일 설정 방법

**꼭 필요한 건 아니에요** — 설정 안 하면 재설정 코드가 API 응답(`demoCode`)과 서버 콘솔에 그대로 나와서 화면에 표시돼요. 실제 이메일로 보내려면:
1. [Resend](https://resend.com/) 가입 → API 키 발급
2. Replit Secrets에 `RESEND_API_KEY` 추가 (필요하면 `MAIL_FROM`도 발신 도메인에 맞게 설정)

## 카카오 알림톡 설정 방법

**꼭 필요한 건 아니에요** — 설정 안 해도 알림은 서버 콘솔 로그 + 관리자 대시보드 "알림 이력" 탭에 기록되는 방식으로 대체돼요. 실제 카카오톡으로 발송하려면:

1. [카카오 비즈니스](https://business.kakao.com/) 에서 채널 만들고 "알림톡" 서비스 신청 (승인까지 며칠 걸릴 수 있어요)
2. [솔라피(Solapi)](https://solapi.com/) 가입 → 카카오 채널 연동 → 발신프로필 키(pfId) 발급 → 메시지 템플릿 등록/승인
3. 솔라피 콘솔에서 API Key/Secret 발급
4. Replit Secrets에 추가:
   - `SOLAPI_API_KEY`, `SOLAPI_API_SECRET`
   - `KAKAO_SENDER_KEY` (발신프로필 키)
   - `KAKAO_SENDER_PHONE` (알림톡 실패 시 SMS로 대체 발송할 발신번호, 사전 등록 필요)

이 과정은 실제 사업자 등록/채널 승인이 필요해서 며칠 걸릴 수 있어요. 코드는 이미 연동되어 있으니, 승인만 받으면 바로 실제 발송으로 전환됩니다.

## Google Gemini API 설정 방법 (처방전 사진 분석 + AI 증상 체크)

**꼭 필요한 건 아니에요** — 설정 안 해도 예약/승인/처방전 전송 등 나머지 기능은 그대로 동작해요. 처방전 화면에서 "분석하기"를 누르거나 홈 화면에서 증상 체크를 시도하면 "Google AI 연동이 설정되지 않았어요" 안내가 뜨고, 처방전 쪽은 "AI 분석 없이 계속하기"로 넘어갈 수 있어요.

### API 키 발급
1. [Google AI Studio](https://aistudio.google.com/apikey) 접속 → 구글 계정으로 로그인
2. "Create API key" 클릭 → 키 발급
3. Replit **Secrets** 탭에 추가:
   - `GOOGLE_AI_API_KEY` = 발급받은 키

그게 전부예요 — 별도 콜백 URL 등록이나 결제 정보 없이 바로 사용할 수 있습니다 (다만 사용량이 많아지면 Google Cloud 프로젝트에 결제 계정 연결이 필요할 수 있어요). **키 하나로 처방전 사진 분석과 증상 체크 두 기능 모두 동작해요.**

### 참고
- 기본 모델은 `gemini-3.5-flash`예요. 다른 모델을 쓰고 싶으면 `GOOGLE_AI_MODEL` 환경변수로 바꿀 수 있어요
- 처방전 분석 결과와 증상 체크 추천 모두 Google AI가 생성한 **참고용 일반 정보**입니다. 실제 처방/진단과 다를 수 있으니, 화면에 "정확한 진단·복용법은 의료진과 상담하라"는 안내를 넣어뒀어요
- 증상 체크가 추천하는 진료과목은 우리 DB에 실제로 존재하는 진료과목 중에서만 고르도록 제한해뒀어요 (검색 안 되는 과를 추천하는 일 방지)
- 처방전 분석(`/analyze`) 단계의 이미지는 저장하지 않고 Google로만 전달돼요. 다만 "전송하기"를 눌러 처방전을 약국에 보낼 때는 사진이 DB에 저장되어 약국 담당자가 다시 확인할 수 있어요

## 자동화 테스트

핵심 흐름(회원가입/로그인/비밀번호재설정/탈퇴, 예약 생성·충돌방지·취소·확정, 처방전 전송·수락·거절·재전송, 리뷰, 관리자 계정관리·입점신청 승인, AI 증상 체크 입력 검증, 복약 알림 스케줄 계산·생성·발송)에 대해 54개의 테스트가 있어요.

```bash
DATABASE_URL="여기에_테스트용_DB_주소" PGSSL=false npm test
```

- **꼭 별도의 테스트 DB를 사용해주세요.** 테스트가 매번 `users`, `bookings`, `prescriptions` 등 트랜잭션성 테이블을 전부 비우고 시작해요 (병원/약국 데이터가 담긴 `hospitals`/`pharmacies` 테이블은 건드리지 않아요). 운영 DB에다 실행하면 실제 사용자 데이터가 지워집니다
- Replit이라면 로컬에 임시 Postgres를 하나 더 띄우거나, 별도의 Replit Database 인스턴스를 만들어서 그 주소로 실행해주세요
- 테스트는 `server/__tests__/` 폴더에 있고, `npm run dev`로 실행 중인 서버와 무관하게 `createApp()`으로 별도 앱 인스턴스를 띄워서 검증해요

## 여전히 단순화된 부분

- 진료 시간 슬롯은 여전히 20개 고정 틀 안에서만 켜고 끌 수 있어요 (실제 병원 예약 시스템 연동 전까지)
- 약관/개인정보처리방침 문구는 데모용 예시라 실제 서비스 전 법률 검토가 필요해요
- 결제(진료비/약값) 연동은 아직 없어요
- 리뷰는 별점 조작 방지를 위한 기본적인 검증(확정 예약/조제 완료 건당 1회)만 있고, 신고/삭제 기능은 없어요
- 세션(JWT) 무효화 기능이 없어서, 로그아웃해도 탈취된 토큰 자체는 만료 전까지 유효해요
- 자동화 테스트는 백엔드 API 위주예요. 프론트엔드(React 컴포넌트) 테스트나 E2E(브라우저) 테스트는 아직 없어요
- iOS Safari에서는 웹 푸시를 받으려면 "홈 화면에 추가"(PWA 설치)가 필요해요 (iOS 16.4+, 일반 브라우저 탭에서는 동작 안 함). 안드로이드/데스크톱 브라우저는 바로 됩니다
- 복약 알림은 식사 시간이 아침 8시/점심 12시/저녁 7시로 고정이라 사용자가 직접 바꿀 수 없어요. "먹었어요" 체크나 오늘의 복약 현황 같은 기능도 아직 없고, 정해진 시간에 알림만 보내요
- 처방전 안에 약이 여러 개여도 복용 기간/횟수는 처방전 전체 기준 하나만 저장해요 (약마다 기간이 다른 경우는 반영 못 해요)

## 데이터 출처

`data/` 폴더의 병원/약국/진료과목 CSV는 사용자가 제공한 **건강보험심사평가원 "병원정보서비스"·"약국정보서비스"·"의료기관별상세정보서비스(진료과목정보)" (2026.3 기준)** 공개 데이터를 가공한 것입니다. 실제 서비스에 사용하시려면 데이터 출처 표기 및 이용 약관을 직접 확인해주세요.

지도는 [OpenStreetMap](https://www.openstreetmap.org/copyright) 타일을 사용하며 API 키가 필요 없습니다.
